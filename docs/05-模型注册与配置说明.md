## 2. 模型注册表 `backend/models/config_model.py`

`MODEL_CONFIG["models"]` 是所有可用模型的唯一权威来源，每个模型含：
- `name` / `provider` / `family`
- `type`：能力类型数组（`llm` / `vlm` / `t2i` / `i2i` / `video`）
- `concurrency`：并发生成上限
- `price_*`：价格元数据
- `capabilities`：结构化能力（见下）

关键函数：
- `get_models_by_type(type)` → 按类型过滤
- `get_model_config(model)` → 单模型元数据（含模糊匹配兜底）
- `get_max_concurrency(model, enable_concurrency)` → 并发数
- `model_records(media_type)` / `list_api_models(...)` → 供 `/api/models` 用
- `media_capabilities()` / `model_ability_tags()` / `_workflow_info()` → 能力标签归一化

## 3. 能力标签（capabilities）

图像/视频模型通过 `capabilities` 描述能力，前端模型下拉据此过滤。核心字段：
- `ability_type`：`image_generation` / `image_to_video` / `reference_to_video` / `video_editing` / ...
- `ability_types` / `adapter_ability_types`：能力标签数组
- `input_modalities` / `adapter_input_modalities`：`["text","image","audio","video"]`
- `api_contract_verified`：是否已验证 API 契约（`verified_only=true` 时只返回 true 的）
- `duration`：`{min, max, integer, verified}`
- `resolutions` / `ratios`

## 4. 三种视频生成模式

| 模式 id | 含义 | 后端字段 | 能力标签 |
|---|---|---|---|
| `first_frame` | 首帧生视频（推荐） | `video_first_frame_model` | `first_frame_i2v` |
| `start_end_frame` | 首尾帧生视频 | `video_start_end_model` | `start_end_frame_i2v` |
| `reference` | 参考图生视频 | `video_reference_model` | `reference_to_video` |

前端 `config/models.ts` 的 `VIDEO_GENERATION_MODES` 维护该映射；`PATCH /api/project/{id}/models` 与 `POST /api/project/start` 都支持这三种字段（并向后兼容旧字段 `video_model`）。

## 7. 前端设置页如何获取模型

设置页通过 `fetchApiModels({ modelType: 'llm'|'vlm'|'t2i'|'i2i'|'video' })` 或 `fetchApiModels({ mediaType:'video', ability:'first_frame_i2v', verifiedOnly:true })` 获取选项，`lib/modelRegistry.ts` 按 provider 分组渲染。保存时调 `PUT /api/config`（全局）或 `PATCH /api/project/{id}/models`（会话级）。
