# 09 · 前端（frontend）：结构、设计系统与实施状态

> 目标：**保留后端不动**，用 `frontend/` 重写 UI 层。
> 原版前端 `xiaoyunque/xiaoyunque/frontend/` **保持不动**，作为运行对照与逻辑参考。
>
> ⚠️ 本文档描述的是**当前已实现状态**。早期这里是「浅色 Lollipop 骨架方案」，
> 该方案已被**深色主题**取代，旧描述不再适用。

## 1. 技术栈与运行

| 项 | 内容 |
|---|---|
| 框架 | Next.js 16（App Router）+ React 19 |
| 样式 | Tailwind CSS 4（`@theme` / 任意值 Token） |
| 语言 | TypeScript |
| 其他依赖 | `clsx`、`tailwind-merge`、`lucide-react` |
| 后端 | Python 3.11 + FastAPI，`http://127.0.0.1:8000` |

```bash
cd frontend
npm install
npm run dev            # 默认 3000；端口被占用时：npx next dev -p 3001
```

### 与后端的连接方式（两条路径，别搞混）

1. **普通 REST + 静态产物** → 走 Next `rewrites` 代理（`next.config.ts`）
   - `/api/:path*` → `${BACKEND_API_URL}/api/:path*`
   - `/code/:path*` → `${BACKEND_API_URL}/code/:path*`
2. **SSE 流式接口**（`execute` / `intervene` / `tasks/{id}/events`）→ 由 `lib/workflowApi.ts`
   用 `NEXT_PUBLIC_API_URL`（默认 `http://127.0.0.1:8000`）**直连后端**，**不走代理**
   （代理会缓冲响应，SSE 会失效）

环境变量：`BACKEND_API_URL`（rewrites 目标）、`NEXT_PUBLIC_API_URL`（SSE 直连目标）。

## 2. ⚠️ 本地开发必须知道的坑

**Next 16 默认只信任 `localhost`。** 若用 `127.0.0.1` 访问 dev server，`/_next/*` 的 JS chunk
会被判定为跨源并返回 **403**。表现是：页面 HTML 能打开，但**客户端 JS 完全不加载、永不
hydration**——所有交互失效、副作用不执行（例如主流程 stage 视图打不开、页面停在「正在读取
默认模型…」）。控制台里是 403 与 HMR WebSocket 失败。

`next.config.ts` 中的 `allowedDevOrigins` 就是为此而设：

```ts
allowedDevOrigins: ['127.0.0.1', 'localhost', '192.168.110.27'],
```

换机器 / 换网段后用新 host 访问，把该 host 加进去；或用 `localhost` 访问。

## 5. 设计系统：深色主题

风格定位：**深色 + 荧光绿强调**（参考 higgsfield.ai）。Token 全部定义在 `app/globals.css`。

### 核心 Token（`--hf-*`）

| Token | 值 | 用途 |
|---|---|---|
| `--hf-bg` | `#0f1113` | 应用画布 |
| `--hf-surface` | `#1c1e20` | 卡片 / 输入框 / 顶栏 |
| `--hf-surface-2` | `#26282b` | 次级表面（内嵌区、禁用态） |
| `--hf-text` | `#f7f7f8` | 主文本 |
| `--hf-text-muted` | `#a8a8a8` | 次级文本 |
| `--hf-text-dim` | `#7a7d80` | 弱化文本 |
| `--hf-accent` | `#d1fe17` | 强调色（主按钮 / 选中态 / 活动导航） |
| `--hf-accent-ink` | `#1a1a1a` | 强调色上的文字 |
| `--hf-accent-soft` | `rgba(209,254,23,.08)` | 强调色淡底 |
| `--hf-border` | `rgba(255,255,255,.08)` | 常规描边 |
| `--hf-border-strong` | `rgba(255,255,255,.14)` | hover / 强调描边 |
| `--hf-radius-sm/md/lg/xl` | `8 / 10 / 12 / 20px` | 圆角 |
| `--hf-shadow-modal` | `0 20px 60px rgba(0,0,0,.6)` | 弹窗阴影 |

### 组件里的用法（Tailwind 4 任意值，无需覆盖 hack）

```tsx
<div className="bg-(--hf-bg) text-(--hf-text)">
  <div className="rounded-(--hf-radius-lg) border border-(--hf-border) bg-(--hf-surface)">
    <h2 className="text-(--hf-text)">标题</h2>
    <p className="text-(--hf-text-muted)">说明文字</p>
    <button className="rounded-(--hf-radius-lg) bg-(--hf-accent) font-semibold text-(--hf-accent-ink)">
      一键生成
    </button>
  </div>
</div>
```

### 按钮规范（统一口径）

| 类型 | 样式 |
|---|---|
| 主操作 | `bg-(--hf-accent)` + `text-(--hf-accent-ink)`（荧光绿底 + 深色字） |
| 次操作 | `bg-(--hf-surface)` + `border border-(--hf-border)` + `text-(--hf-text)` |
| 选中 / 激活 | `bg-(--hf-accent-soft)` + `text-(--hf-accent)` |
| 危险操作 | 语义红（`--lp-error` / `--lp-error-hover`） |
| 状态色 | 绿=完成、琥珀=警告、红=失败（保留色相，按深底调亮） |

### 两套 Token 的关系

- `--hf-*`：**新写 UI 层**使用（`AppShell`、`settings` 等）
- `--lp-*`：早期从原版复制的组件沿用，已**整体深色化**
  （`--lp-canvas-app` / `--lp-surface` / `--lp-action-primary` 等指向同一套深色值）

## 6. 兼容层：Legacy light-surface normalization（重要）

### 为什么存在

`Sandbox`、`PipelinePage`、`stages/*` 是从原版**复制**过来的组件，内部仍大量使用浅色 Tailwind
工具类（`bg-white`、`text-gray-*`、`border-gray-*`、`bg-blue-*` …）。为了不重写组件就能统一到
深色主题，`globals.css` 里有一层显式映射，把这些工具类指向深色 Token。

### 它做了什么

- 表面：`bg-white` → `--hf-surface`；`bg-gray-50/100` → `--hf-surface-2`
- 文字：`text-gray-900/800/700` → `--hf-text`；`text-gray-600/500/400` → `--hf-text-muted`
- 边框：`border-gray-100/200` → `--hf-border`；`border-gray-300` → `--hf-border-strong`
- 强调：蓝 `blue-*` / 靛 `indigo-*` → 荧光绿 `--hf-accent`
- 语义色：`red / rose / amber / emerald / cyan / purple / violet` 保留色相并按深底调亮
- 细节：渐变停靠点、`hover:bg-*-100`、以及 `[class~=…][class~=…]` 组合选择器
  （用于把强调按钮上的白字改成深色字、统一各 stage 自带的紫/绿/玫红操作按钮）

同文件里还有一层更早的 `xyq-*` 覆盖（服务于 `HomePage` / `TopBar`），与上面这层是同一思路。

### 使用约束（务必遵守）

- **新写组件必须直接用 `--hf-*` Token**，不要再引入浅色工具类
- 某个组件迁移到语义 Token 后，**同步删除**它在兼容层里的条目
- 兼容层集中在 `globals.css`，便于检索；改完必须按 §8 自检

## 8. 自检清单（改样式后必做）

1. `npx tsc --noEmit` 通过
2. 浏览器逐页检查**计算样式**，确认无浅色残留：目标元素
   `getComputedStyle(el).backgroundColor` 不应出现纯白 / 浅灰 / 蓝色
3. 覆盖全部 12 个视图：`/`、`/sandbox`、`/settings`、3 个 `/pipelines/*`，
   以及主流程 6 个 stage（stage 需一个历史会话：`/?session=<id>&stage=<stage>`）
4. 标题不被顶栏遮挡（滚动到顶部、以及滚动过程中都要看）
5. 控制台无 error（浏览器扩展注入属性导致的告警除外，见 §9）

## 9. 已知约定与技术债

1. **全局只有一条顶栏**：`AppShell` 顶部导航是唯一顶栏。页面内**不要**再加同质顶栏。
   （原 `BrandHeader` 已删除——它只是把全局导航里的 Logo 又重复了一遍。）
2. **页面根节点不要加 `overflow-y-auto`**：会形成嵌套滚动容器，使内部 `sticky top-16`
   的元素改为相对它计算而**下移 64px**，从而压住页面标题。3 个 pipeline 页曾因此出现
   「标题显示不全」，已修复。
3. **`<body suppressHydrationWarning>` 不要删**：部分浏览器扩展（如 `mpa-extension-id=…`）
   会在 hydrate 前给 `<body>` 注入属性，触发 React 的 hydration 不匹配告警。这与业务代码
   无关，按 React 官方建议在该元素上抑制。
4. **契约层 `lib/`、`config/` 与原版保持一致**，不要为了 UI 需要而改它们。
5. **技术债**：`globals.css` 中 `.xyq-sidebar*`、`.xyq-shell`、`.xyq-main`、`.xyq-task-panel`、
   `.xyq-task-item`、`.xyq-settings-menu` 已无组件引用（旧侧边栏壳的遗留），可在确认后清理。
