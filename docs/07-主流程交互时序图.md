# 07 · 主流程交互时序图

> 本文用时序图 + 状态机图描述主流程（6 阶段工作流）前后端交互，供重写前端时对齐节奏。

## 1. 完整流程时序（含停点）

```mermaid
sequenceDiagram
    autonumber
    participant U as 用户
    participant F as 前端(Next.js)
    participant B as 后端(FastAPI)

    U->>F: 输入创意/风格/模型，点"开始创作"
    F->>B: POST /api/project/start
    B-->>F: { session_id, status, params }
    Note over F,B: session_id 全流程唯一标识

    loop 每个阶段 (script→character→storyboard→reference→video→post)
        F->>B: POST /api/project/{id}/execute/{stage}
        B-->>F: SSE: progress / heartbeat / stage_complete / error
        Note over F: parseStreamEvents 逐行解析
        F->>B: GET /api/project/{id}/artifact/{stage}
        B-->>F: { stage, artifact }
        F-->>U: 渲染阶段产物

        alt 需要用户确认/选择 (status=waiting)
            U->>F: 确认/选择/修改
            F->>B: PATCH /api/project/{id}/artifact/{stage}
            B-->>F: { status: ok, status_map }
        else 需要重新生成
            U->>F: 修改提示词/重生成
            F->>B: POST /api/project/{id}/intervene (SSE)
            B-->>F: SSE 进度 → 新产物
        end

        U->>F: 点"继续"
        F->>B: POST /api/project/{id}/continue
        B-->>F: { status: ready, next_stage }
    end

    B-->>F: post_production 完成 → final_videos
    F-->>U: 展示最终成片（分集视频）
```

## 2. 阶段状态机

```mermaid
stateDiagram-v2
    [*] --> pending: 创建会话
    pending --> running: execute/{stage}
    running --> waiting: 有产物待选择
    running --> completed: 无待选，直接完成
    running --> error: 执行失败
    running --> stopped: 用户停止
    waiting --> running: intervene(重新生成)
    waiting --> completed: 用户选择 + continue
    completed --> running: 进入下一阶段 execute
    error --> running: 重新 execute
    completed --> [*]: 全部阶段完成
```

状态值：`pending` / `running` / `waiting` / `completed` / `stopped` / `error`。
`GET /api/project/{id}/status` 返回**每个阶段**一个状态（`status` 是映射，非单一值）。

## 3. SSE 事件时序（execute/intervene）

```mermaid
sequenceDiagram
    participant F as 前端
    participant B as 后端
    F->>B: POST /execute/{stage} (Accept: text/event-stream)
    loop 生成过程中
        B-->>F: {"type":"progress","phase":"剧本生成","step_desc":"...","percent":50}
        B-->>F: {"type":"heartbeat"}
    end
    B-->>F: {"type":"stage_complete","stage":"...","status":"completed","requires_intervention":false,"payload_summary":{...}}
    Note over F: parseStreamEvents 遇 stage_complete/error 视为终态
    opt 出错
        B-->>F: {"type":"error","message":"..."}
    end
```

前端注意：`execute`/`intervene`/`tasks/{id}/events` 必须直连 `NEXT_PUBLIC_API_URL`（默认 `http://127.0.0.1:8000`），不能走 Next 代理。

## 4. 修改 / 续写 / 重生成流程

```mermaid
flowchart TD
    A[阶段产物已展示] --> B{用户意图}
    B -->|改提示词/描述| C[PATCH /artifact/{stage}]
    B -->|重新生成某些项| D[POST /intervene<br/>modifications: regenerate_xxx]
    B -->|剧情续写| E[POST /execute/script_generation<br/>带续写参数]
    C --> F[GET /status 确认状态流转]
    D --> G[SSE 进度 → 新版本写入 versions]
    E --> H[续写预览状态 waiting<br/>产物含 new_episodes]
    F --> I[POST /continue 进下一阶段]
    G --> I
    H --> I
```

### 重生成关键字段

| 阶段 | modifications 键 | 值 |
|---|---|---|
| character_design | `regenerate_characters` / `regenerate_settings` | id 数组 |
| reference_generation | `regenerate_scenes` | segment_id 数组 |
| video_generation | `regenerate_clips` | segment_id 数组 |

后端会**合并**重生成结果（保留 `selected` 与旧 `versions`，追加新版本），不会覆盖用户已选内容。

## 5. 停点清单（Agent/前端对齐）

| 停点 | 阶段 | 产物确认内容 |
|---|---|---|
| 0 | 创建项目前 | 创意、集数、风格、比例 |
| 1 | 创建项目前 | 模型与参数配置 |
| 2 | script_generation | 全集剧本 |
| 3 | character_design | 角色/场景图选择 |
| 4 | storyboard | 分镜列表 |
| 5 | reference_generation | 参考图选择 |
| 6 | video_generation | 视频片段选择 |
| 7 | post_production | 成片（无需确认，直接交付） |
