# 01 · 项目总览与架构

## 1. 产品定位

**小云雀 XiaoYunQue** 是一个本地部署的 AI 短片/短剧创作系统。用户给一句创意，系统经 6 个阶段编排，产出可查看/可确认/可修改/可续写的中间资产，最终交付完整成片。它不是单点"文生视频"黑盒，而是"可协作的 AI 导演团队"。

## 2. 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Python 3.11 + FastAPI + Uvicorn，`uv` 管理依赖 |
| 前端 | Next.js 16.3 + React 19 + TypeScript + Tailwind CSS 4 + lucide-react |
| 模型 | LLM / VLM / 图像 / 视频多厂商（DashScope、火山方舟 ARK、可灵 Kling、OpenAI、Gemini、DeepSeek） |
| 持久化 | 本地 JSON 文件（`backend/code/`），无数据库 |
| 视频处理 | ffmpeg（拼接与音视频后处理） |

## 5. 主流程状态机

`core/orchestrator.py` 维护每个会话（session）的 6 阶段状态：

```
script_generation → character_design → storyboard → reference_generation → video_generation → post_production
```

每阶段状态值：`pending`（未开始）/ `running`（执行中）/ `waiting`（已产出，待用户确认）/ `completed`（已确认）/ `stopped`（手动停止）/ `error`（出错）。

**核心交互节奏**（前端必须理解）：

1. `POST /api/project/start` 创建会话 → 拿到 `session_id`
2. `POST /api/project/{id}/execute/{stage}` 执行某阶段（SSE 流式返回进度）
3. 阶段完成 → 状态 `waiting`（有待选择）或 `completed` → `GET /artifact/{stage}` 拿产物
4. 用户在前端选择/修改 → `PATCH /artifact/{stage}` 保存，或 `POST /intervene` 重新生成
5. `POST /api/project/{id}/continue` 进入下一阶段
6. 最后 `post_production` 出成片

## 6. 三类功能形态

| 形态 | 入口 | 特点 |
|---|---|---|
| 主流程（6 阶段） | `/api/project/*` | 阶段化、有人工停点 |
| 一次性 Pipeline | `/api/pipelines/*` + `/api/tasks/*` | 后台跑、无停点、SSE 进度 |
| 临时工作台 Sandbox | `/api/sandbox/*` | 单次 LLM/VLM/文生图/图生图/视频 |

三种 Pipeline：`standard`（文艺短视频）、`action_transfer`（动作迁移）、`digital_human`（数字人口播）。
